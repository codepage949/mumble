# 웹페이지 문구와 상태 표시 정리

## 배경

- 현재 첫 화면 문구가 전사 앱 구현 설명에 치우쳐 있어 실제 사용 흐름에 비해 장황하다.
- 상태 표시가 옵션 입력 영역 바로 아래에 단순 텍스트로 놓여 있어 설정 항목과 시각적으로 구분되기 어렵다.

## 계획

- 앱 제목은 `mumble`로 두고, `whisper.cpp`의 도움을 받는다는 짧은 출처 문구만 남긴다.
- 파일 드롭 영역의 설명에서 모델 URL 같은 구현 세부 설명을 제거한다.
- 상태와 진행률을 별도 패널로 묶어 옵션 영역과 명확히 구분한다.
- 정적 HTML 테스트로 핵심 UI 문구와 상태 패널 구조를 검증한다.

## 구현

- 페이지 상단 제목을 `mumble`로 정리하고 `Powered by whisper.cpp` 출처 문구를 추가했다.
- 드롭 영역 설명에서 모델 URL 언급을 제거하고, 파일 투입 문구만 짧게 남겼다.
- 언어 선택, 옵션 라벨, 상태, 로딩, 결과 제목처럼 사용자에게 보이는 문구를 한글화했다.
- `status-panel`을 추가해 상태와 진행률을 옵션 입력 영역과 시각적으로 분리했다.
- getdesign.md의 Cal.com 계열 디자인 설명을 참고해 중립적인 표면, 얇은 경계, 작은 radius, 흑백 강조색 중심으로 스타일을 정리했다.
- 상태 표시는 별도 카드보다 낮은 상태 바처럼 보이도록 muted 배경과 얇은 테두리로 조정했다.
- `deno task dev`를 추가해 산출물 서버를 띄우고, `app` 디렉터리 변경 시 직접 감지해 `scripts/build-whisper-wasm-static.sh` 재실행 후 서버를 재시작하도록 했다.

## 테스트

- `tests/whisper-wasm-remote-model-assets.test.js`에 웹페이지 문구와 상태 패널 구조 검증을 추가했다.
- `deno task dev`와 개발 서버 감시 스크립트 구성을 정적 테스트로 검증했다.
- `deno task dev` 실행 중 `app/index-tmpl.html`을 임시 수정하고 되돌려, 재빌드 후 서버가 계속 살아 있는지 확인했다.
- `curl -I http://localhost:8000/`
- `deno task check`
